# 应用维护权限与设计工作流

Web、桌面、交互 CLI 和 headless CLI 在创建运行上下文时启用 `applicationProtection`。它不来自请求正文或模型参数，子智能体继承该约束。

应用代码、界面、安装文件、系统提示词和核心配置的修改，仅允许通过当前账户服务实时核验的应用管理员执行。沿用现有权限体系，必须同时具备 `admin.read`、`roles.write`、`settings.write`；只可查看管理后台的账户不具备维护权限。核验失败、离线、会话失效、账户变化或权限撤销均拒绝修改，不退回本地身份声明。

工具派发在执行 hooks 前、权限决策中及最终执行前检查受保护目标。Full 模式、会话允许规则、技能允许列表和模型传入的 `isAdmin` 均不能给普通用户授予此项权限。管理员通过身份核验后，仍遵守原工具权限与输入校验。`/export`、`/rewind`、`/memory edit` 的文件修改入口也遵循该规则。

路径检查覆盖当前应用安装目录、已识别的源码目录、应用/项目核心配置，解析相对路径、父目录和符号链接/Windows junction。结构化文件路径、嵌套工具参数、终端命令和第三方内联脚本中明确可识别的路径都会检查。读取应用文件、编辑独立用户项目和正常设计任务保留原有能力。用户在设置页面配置自己的模型、权限偏好与插件仍使用原有配置流程。

按产品选择保留 PowerShell、Bash、MCP 和其他任意脚本执行能力。因此本功能是明确目标的访问控制，不是操作系统沙箱；无法保证拦截动态拼接、编码、间接脚本、第三方插件内部行为或无路径的 UI 操作。普通用户不能通过受控入口明确修改应用，但不能据此宣称本机恶意代码已经被完全隔离。

主智能体与子智能体共用泛设计指导，涵盖建筑、城市规划、风景园林和城市更新：沿用项目上下文，明确尺度/阶段/成果，仅询问关键缺项，区分事实与假设，统一单位及指标口径，核实规范版本，优先专业工具和结构化批量操作，分阶段核验，交付真实可点击文件。自定义输出风格不能移除这些指导及应用保护规则。

验证：`npm run test:application-protection` 检查普通用户/管理员、权限撤销、离线、伪造角色、路径/命令/MCP/嵌套调用、junction、hooks 和 slash 导出；`npx tsx src/scripts/test-agent-runtime-scope.ts` 检查子智能体继承与实际派发；`npm run test:tool-parity` 检查 CLI/Web 真实入口一致性。所有这些验证均使用本地模拟账户/模型，不调用收费模型。
