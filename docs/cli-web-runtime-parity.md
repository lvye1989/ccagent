# CLI / Web 连续执行、响应与上下文检查

本轮检查日期：2026-11-10。CLI 与 Web 共用真实 QueryEngine、工具派发、权限、模型目录与上下文引擎；没有另建一套 Web 模拟执行器。开发过程中的本地模型模拟仅替代供应商响应，用于可重复测试实际引擎、HTTP/SSE 和文件工具。

## 修复内容

### 任务连续性

- Web 原先每秒轮询一次后台通知，改为与 CLI 一致的事件订阅和空闲后立即续跑，保留1秒兜底扫描。通知按归属会话和到达顺序处理，合并同批通知；其他任务或审批占用时等待，不绕开权限。
- Web 自动和手工压缩后写入与 CLI 相同的会话快照。服务重启后使用已压缩的上下文，不重新装回全部旧历史。
- 修复了两端共有的“轮前自动压缩后丢失本轮新要求”问题：成功摘要的持久化检查点延后至本轮要求及附件准备完成之后发布。已实证修复前重启丢失，修复后正常完成、主动停止两种路径均保留新要求恰好一次。
- SSE 回放缓存不足、游标无效或服务重启导致游标失效时，前端重新读取完整会话与待审批状态。恢复不重发用户任务；原连接回调不能污染新状态。
- 自动恢复快照遇到临时网络/5xx错误时，以250ms至5秒的退避重读，保留 EventSource 自身重连。恢复保留当前页面和导航意图；会话被删除时清理状态，不无限重试404。
- 定时任务按引擎真实结束原因处理。模型失败、停止或达到轮数限制时暂停，保留结果，不误标成功或自动再开一轮。

### 上下文与速度

- 压缩失败计数改为每个 QueryEngine 独立管理，避免多个 Web 会话相互触发熔断。
- 自动及手工摘要继承停止信号；摘要失败保留原上下文，同一批失败历史不立即重复发摘要请求。后续工具结果增长和真实供应商上下文溢出仍可恢复。
- 微压缩按 `tool_use.id` 对应工具名处理原始 Read/PowerShell 等结果，不依赖正文前缀；保留最近8条消息、错误结果及工具配对。避免为判断变化反复序列化完整历史。
- 将本次请求实际工具定义纳入 token 预算；已有供应商用量只补工具定义新增量，避免重复累计。动态 MCP、模型切换、恢复历史和清空上下文均有回归。
- 中文等非 ASCII 文本采用更保守估算，减少长中文输入、重启后零用量历史低估的风险。
- 摘要请求关闭额外思考；主任务思考设置、权限及工具清单继续沿用原配置。

## 可重复基准

运行前先构建：

```powershell
npm.cmd run build
npm.cmd run test:runtime-parity
npm.cmd run test:context
```

新增回归已接入 `test:web`、`test:context` 和其上层 `verify:release`。

`src/scripts/test-cli-web-runtime-parity.ts` 使用相同隔离账户、模型、工作区与权限，实际启动编译后的 CLI/Web，检查7组场景：

1. CLI 和 Web 各3次短任务延迟采样，普通任务没有额外摘要。
2. 两端 Read→Write→Read，结果一致。
3. 两端18轮连续工具操作，中间一次缺文件错误后继续完成。
4. 同一 Web 会话追加要求，保留前文证据。
5. 工具执行期间断开 SSE，再连接后没有重复工具调用。
6. 80K字符 Read 结果触发一次摘要，保留任务目标并完成后续操作。
7. 隔离 Web 进程重启后恢复历史，并继续处理追加要求。

最终基准共15个任务回合、68次本地模拟模型请求，其中66次主请求、2次摘要；实际文件工具调用51次，两次缺文件错误是主动注入并验证恢复。短工具任务两端均4次主请求、0次摘要；长上下文任务两端均4次主请求、1次摘要。

最终构建在无其他回归并行的窗口复测：热 Web 的3次采样中，首事件中位数4.2ms，首文本105.8ms，完成171.2ms；冷 CLI 完成中位数886.2ms。模型首token至 Web 文本事件额外0.9至3.2ms。首次模型请求至终态的中位数，CLI约100ms、Web约97ms（CLI还包含进程结束，口径仍有差别）。未发现明显的 Web 流式等待；小样本不能用于承诺整体推理提速，也不能把冷 CLI 与热 Web 的总时间直接比较倍数。

后台续跑专项的编译产物隔离实测：后台任务释放至父模型请求88ms；另一前台任务释放后至归属父请求86ms。包括历史准备与写盘，不包含真实供应商推理时间。

## 其他专项验证

- 新上下文连续性：18个行为场景，包括摘要停止、失败保留、中文恢复、动态工具增长、同历史失败去重、真实413恢复及当前用户要求的检查点/取消边界。
- 新 Web 连续性：10个场景，包括620条事件溢出、问题/审批恢复、审批中停止及过期答复拒绝、压缩后重启、定时任务失败/停止、50轮 Read 达到限制后的正确暂停，以及轮前自动压缩后正常/停止重启保留本轮要求。
- 编译产物中断、后台通知和Web连续性均单独验证。另有真实 QueryEngine + 会话存储组成的 CLI TUI 同序持久化测试，验证摘要后新需求在运行态与恢复态均恰好一次；这不是终端界面的按键自动化。
- DOM测试覆盖临时快照失败重试、用户图片消息文字恢复、旧连接隔离、待审批恢复、后台导航保留、删除会话的终止处理。

旧 QueryEngine golden 的上下文数字已有文案漂移；本轮只更新了系统提示、工具定义和相关合计的预期数字，未改其他命令预期，断言仍保持完整事件比对。

全量回归还发现一条过时的 MCP OAuth 凭据目录断言：安全存储现保留事务哨兵，旧测试把它也计为凭据。现精确要求1个规范加密凭据 JSON及其对应事务文件，并拒绝额外文件；原有PKCE、账户隔离、刷新令牌、并发和取消检查继续保留，9项OAuth回归通过，没有修改生产OAuth逻辑。

最终隔离全量 `npm.cmd run verify:release` 已通过，耗时507秒。冻结快照包含666个文件，运行结束逐项哈希一致，命令退出码0。包括新上下文/CLI持久化、Web连续性、双入口基准和原有权限、账号、工具、插件、白板与独立包工作流。

并行执行多套回归时，编译产物的一次50轮场景曾超过20秒测试等待时限；保留原始记录，未改业务代码或该时限的两次复测均通过。曾出现的冷 CLI 启动离群在最终安静窗口没有复现。此结果验证当前功能机制，不作为高并发时延保证。
