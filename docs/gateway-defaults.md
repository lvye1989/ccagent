# 平台默认路由与首次配置（2026-11-07）

本轮落实 [临时记录](../临时记录.md) 的平台默认路由设置。管理员可分别保存主模型、视觉读图、Jev 决策、联网搜索和语音合成的默认路由，用于新账户首次验证个人 CCAGENT Key 后的初始选择；已有选择和用户主动清空的选择不被覆盖。辅助服务启用和新对话默认模型仍须用户明确操作。

## 管理与目录

后台“服务网关”新增“平台默认服务”表单。候选项按服务类型分开，只能选择已开放、协议受支持、凭据/成本/汇率有效的路由；未就绪选项保留名称并禁用。已保存路由后续停用或失效时显示提示，管理员可以重新选择或清空；不会自动选用另一条付费路由。

默认配置存于现有 `settings` 表的独立 `service_default_routes` 项，没有新增表或 SQL 迁移，也没有扩张原系统设置的五字段保存白名单。`GET/PUT /api/admin/routes/defaults` 要求实际登录和 `routes.write`，写入还验证同源、五类字段、路由编号与配置版本。路由/价格写入与默认配置共用有界管理锁；校验和默认配置写入在同一事务，校验失败不部分保存，旧版本冲突返回 409。未变更的保存不增加版本或审计。

路由就绪检查与配置读取可复用当前事务连接，避免单连接池在事务中再次借用自身连接。该事务能力由既有查询函数显式接受读取器实现，沿用 [Drizzle 事务接口](https://orm.drizzle.team/docs/transactions)，没有改变资金函数、运行权限或上游请求。

管理接口只返回五类选择、版本和候选项的编号、名称、服务类型、配置就绪状态；不返回供应商凭据名或密钥。每次实际变更写入操作人、时间、`routes.defaults.update`、对象及变更服务名和新版本；此处不进行供应商连通或收费请求。

`GET /v1/models` 在原数据外增加 `defaults`：五类服务映射到当前目录中可用的路由编号，未配置或失效为 `null`。服务失效时保留管理员已保存的意图供后台核对，但不向客户端推荐另一个路由。仍要求有效邮箱密码会话及属于该用户的个人 CCAGENT Key，目录不能绕过登录。

## CLI、Web 与桌面接续

客户端验证默认字段格式、编号及服务类型；无效推荐使目录验证失败，原配置与加密 Key 不被改写。兼容未提供 `defaults` 的旧服务。仅在没有现有绑定、且用户没有明确提交选择时，使用服务器推荐初始化角色；刷新保留有效旧选择，失效角色继续按既定规则清除，不自动填上新推荐。

最终写入在账户文件锁内重新读取当前绑定，较慢的首次验证不能覆盖另一窗口刚保存的选择或空选择。没有显式提交新 Key 的刷新，如果另一窗口已更换本机 Key，则明确拒绝，避免写回旧 Key。

Web 首次验证仅提交平台 Key，随后显示推荐及价格；首次验证阶段的辅助服务和默认聊天模型开关禁用。验证成功后由用户保存选择并决定是否开启辅助服务或设为新对话默认。修正了旧表单首次提交空角色对象、导致推荐被覆盖的问题。桌面向导原已分开验证 Key 与保存选择，沿用同一客户端初始化逻辑；CLI 验证 Key 也使用该逻辑，不额外调用模型。

不可用提示通过 `aria-describedby` 关联，五个控件名称保持稳定，便于键盘和辅助技术定位。该改进没有增加生图能力；`vision` / “视觉读图”继续表示图片输入分析，OpenAI 生图仍待此前凭据选择。
