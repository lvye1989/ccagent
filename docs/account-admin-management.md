# 用户、API Key 与金额管理

管理员通过 `/admin/keys` 查询、创建、编辑和删除个人平台 API Key，通过 `/admin/users` 查看角色和用户余额并调整余额。页面入口与对应 API 均校验当前会话的业务权限。

## API Key

- 查询沿用用户邮箱或编号、名称、状态和日期筛选，支持分页与 CSV 导出。
- 创建时先按邮箱确认所属用户，再填写名称和可选累计消费上限。完整 Key 只在创建成功时显示一次，关闭后无法查询明文；后台只保存哈希和前缀。
- 编辑可修改名称与累计消费上限。限额留空表示不单独限制，限额不能低于该 Key 的已使用金额与冻结金额之和。账户可用余额仍独立限制调用。
- 删除会立即撤销该 Key，阻止新的调用。已有调用继续按原授权结算，历史 Key、调用和财务记录保留用于核对。
- 以上操作需要 `keys.write`；普通用户无法调用管理员接口。

## 用户余额

用户列表在“角色”后展示“用户余额（元）”，表示账户总余额，其中可能包含进行中调用冻结的部分。管理员可选择增加余额、扣减余额或设置目标余额，须具有 `wallets.write` 并填写操作原因。

修改通过原资金流水函数入账，记录操作人、原因及金额；使用账户锁和幂等编号防止并发覆盖与重复入账。设置余额不能低于已冻结金额。重试同一个操作不会再次修改余额，也不会把期间发生的正常消费覆盖回旧数值。

## 金额单位

用户界面中的余额、额度、费用、充值、退款及对应 CSV 金额以人民币元展示和填写。小额费用最多保留六位小数，例如 `0.000001` 元；充值金额仍遵守支付渠道精确到分的要求。

内部账本与既有机器 API 保留整数微元，支付渠道继续使用整数分，避免浮点计算及数据迁移影响历史账单。换算只在界面输入、展示与人读导出边界完成。供应商成本币种按其公开报价保留，人民币结算结果统一为元。

管理员操作留有审计记录；完整平台 Key、供应商 Key 与登录凭据不写入操作审计或 CSV。
