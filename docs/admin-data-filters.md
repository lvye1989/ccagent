# 后台组合筛选与汇总（2026-11-07）

后台原先只有单一关键词，导出也只传递关键词。现在列表、分页、金额汇总和授权导出使用同一套经校验的筛选条件；任务费用先筛选实际调用，再按用户和任务分组。

本文保留筛选阶段的部署和原始验证范围。后续到期待处理筛选、北京时间表格展示及当前开发部署见 [后端健康与设置记录](backend-operations.md)。

## 使用方式与口径

后台各列表显示适用的用户邮箱或编号、开始/结束日期、状态、服务类型、服务编号、任务编号及关键词。用户邮箱支持忽略大小写的片段匹配，用户编号、服务编号和任务编号按完整值匹配。关键词中的 `%`、`_` 和 `!` 按普通字符搜索。

| 列表 | 可组合的条件 | 时间口径 / 汇总 |
| --- | --- | --- |
| 用户、Key | 用户、状态、关键词、日期 | 创建时间 |
| 账户余额 | 用户、关键词、日期 | 钱包更新时间；合计当前余额和冻结金额 |
| 充值订单 | 用户、订单状态、关键词、日期 | 创建时间；合计所选状态的订单金额 |
| 退款 | 用户、退款状态、原订单关键词、日期 | 创建时间；合计申请退款金额 |
| 调用、任务费用 | 用户、日期、调用状态、服务类型、服务编号、任务、到期待处理及关键词 | 调用创建时间；费用和授权额度或调用次数合计 |
| 资金流水、审计 | 用户 / 操作人、关键词、日期 | 创建时间；资金流水汇总余额及冻结变动 |
| 服务网关、成本版本 | 服务类型、关键词、日期；网关可选启停状态，成本可选服务编号 | 网关更新时间 / 成本生效时间 |
| 角色、权限 | 名称关键词；角色可选日期 | 角色创建时间 |

日期按北京时间，包含结束日期全天，使用“起始日零点 ≤ 时间 < 结束日次日零点”。数据库明确使用 `Asia/Shanghai` 转换，避免依赖连接时区；参见 [PostgreSQL 日期与时区规则](https://www.postgresql.org/docs/17/functions-datetime.html)。钱包日期用于选择最近更新的账户，显示其当前余额。核对充值入账或成功退款金额时，应选择相应状态。

服务类型按当前服务目录匹配，历史金额读取已保存的结算值。任务按“用户 + 任务编号”分组，两个用户的相同任务编号不会合并。汇总覆盖全部匹配记录；每页只展示选定条数。逐笔调用与任务汇总之间切换保留条件，重新筛选回到第一页。

“导出当前筛选 CSV”保留全部条件并导出前 10,000 条，不受当前页限制；超出上限时页面明确提示继续筛选，合计仍覆盖全部匹配记录。导出继续检查列表权限及 `data.export`，记录行数、总数、条件字段和条件摘要，不把输入的邮箱、关键词或完整密钥写入审计元数据。

## 接口与一致性

`GET /api/admin/data/{section}` 支持 `q`、`user`、`from`、`to`、`status`、`service`、`route`、`task`，以及原有 `page`、`pageSize` 和 `format=csv`；各列表仅接受上表适用字段。后续增加的 `overdue` 仅用于调用/任务列表，只接受 `true` 或空值，筛选达到核对期限的进行中或待对账调用。JSON 返回新增 `filters` 和 `summary`，保留原有 `rows`、`total`、分页字段及 `q`。

无效日期、逆序日期、重复参数、未知参数、无效状态或不适用的条件返回 400，不能静默退化为全量导出。页面显示可修正的错误并隐藏导出和记录，清除条件后恢复列表。分页保留筛选；筛选变化时重置管理操作表单，避免沿用先前列表的操作对象。

所有值继续经 [Drizzle 参数化 SQL](https://orm.drizzle.team/docs/sql) 绑定，表和列从服务端白名单选择。列表和总数/合计在一个只读 `repeatable read` 事务中读取，采用同一快照；其语义见 [PostgreSQL 事务隔离](https://www.postgresql.org/docs/17/transaction-iso.html)。没有改变认证、RLS、运行角色、账本写入函数、金额或计费规则，没有新增数据库迁移。
