# Web 与 CLI 响应速度修复（2026-11-10）

## 问题与修复

1. **网关上下文容量配置错误。** 正常启动后共有 196 个工具，其中 150 个来自 MCP；工具定义约 241,121 字符，实际模型输入约 67,000–70,000 token。生产 `deepseek-main` 指向 `https://api.deepseek.com` 的 `deepseek-flash`，目录却声明 32,768 token，导致读取几行文件也插入一次摘要请求。依据 [DeepSeek 官方模型元数据](https://api-docs.deepseek.com/api/list-models/)及[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)，通过正常管理员接口、使用 `expectedUpdatedAt` 乐观锁，仅将 `options.contextWindow` 修正为 **1,048,576**。已逐字段回读确认：单价与价格版本、上游地址及模型、输出上限 2,048、图片上限 0、备用配置、凭据引用均保持原值，并刷新本机服务目录。没有通过放宽本地阈值覆盖管理员配置。

2. **上下文用量重复计算与锚点不准。** 供应商输入用量已包含系统提示和工具定义，原估算再次加入系统提示；工具返回后又把锚点错误移到消息末尾，漏算新结果。现在记录实际请求对应的 assistant、系统提示及模型，只补后续消息和系统提示增长。恢复历史的零用量回退完整估算；压缩、消息替换和模型切换使旧锚失效。必要压缩、硬限制与取消仍保留。

3. **Web 新会话多一次读取。** 创建接口返回完整初始 `snapshot` 和 SSE 游标；前端复用对应会话快照，省去创建后的 GET。打开历史、重新连接仍重新读取；旧服务没有快照时正常回退。发消息和执行工具仍走原有身份、权限检查。

4. **重复传输完整历史。** `messages_updated` 原来多次传送完整历史，前端没有消费该事件。现在不序列化、发送或缓存该快照；恢复仍使用会话 GET，保留工具结果、用量和增量文本事件。

5. **逐段输出重复布局。** 首段文字立即显示，后续按 30ms 合并，复用单一文本节点追加，待刷新缓冲限制在 32KiB 以下。正常完成、中断和异常保留末批文字；重试、切换会话和新任务取消旧缓冲。

6. **并发认证重复往返。** 同一账户、同一凭据版本仅合并同时在途的验证，不增加缓存期限；顺序请求仍在线校验。凭据提交、删除和条件删除复用跨进程短文件事务，避免旧请求拒绝时误删新登录。加密和网络等待保持在锁外。
