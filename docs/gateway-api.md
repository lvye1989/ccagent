# CCAGENT 云端网关接入约定

当前为开发实现。云端已部署受访问保护的 Preview，尚未正式上线。本地客户端已接入强制登录、个人平台 Key、官方服务选择、大请求私有上传和调用状态查询；原生客户端经真实 HTTP、隔离数据库与私有存储调用 DeepSeek 和 Qwen 语音已通过。其余供应商、邮件、支付及成品安装流程仍需分别验收。

## 身份和请求标识

网关同时要求有效的 Better Auth 应用会话 Cookie，以及属于该账户的个人 CCAGENT Key。Key 不能替代邮箱密码登录。原生客户端通过登录接口取得签名 Cookie，在 Windows 使用 DPAPI 安全保存；不得保存密码或供应商密钥。

- `Authorization: Bearer <个人 CCAGENT Key>`
- `Cookie: <邮箱密码登录返回的会话 Cookie>`
- `Idempotency-Key: <每次业务调用固定的唯一标识>`，重试相同调用沿用该值。
- 调用标识为 1–200 个 ASCII 字母、数字或 `._:-`，创建与查询使用同一校验规则。原生客户端使用 UUID；保留网关原有的其他合法编号。
- `X-CCAGENT-Task-Id: <任务标识>`，同一任务可包含多次不同调用；留空使用本次幂等标识。
- `X-CCAGENT-Price-Version: <目录显示的价格版本>`，原生客户端固定此值；首次调用时价格已改变返回 `409 PRICE_CHANGED`，不冻结或调用供应商，用户刷新目录后再确认。原调用重放继续使用原快照。
- `X-CCAGENT-Price-Fingerprint: <目录 pricing.fingerprint>`，固定公开成本、汇率、模型映射和输入/输出/图片限制；变化同样返回 `409 PRICE_CHANGED`。普通旧客户端可省略指纹，启用备用时必须提供。
- 显式允许备用时，还须同时提供 `X-CCAGENT-Fallback-Route`、`X-CCAGENT-Fallback-Price-Version`、`X-CCAGENT-Fallback-Price-Fingerprint`，取自当次已确认的备用目录条目；不能仅传备用编号。缺少完整确认返回 400，管理员映射、就绪或价格发生变化返回 409，均在冻结前拒绝。
- 浏览器请求仅接受应用自身来源。管理、账户与文件写入接口还要求准确的 `Origin`；原生客户端也应按服务地址设置该请求头。

幂等键绑定当前用户、Key、路由、任务及完整请求哈希。修改请求却复用旧键返回 409；已执行的请求不会再次访问供应商。在结果有效期内可重放已完成的私有结果；已过期或未能保存的结果不触发重新执行。

## 客户端配置

Web / 桌面在“设置 → 官方服务”验证个人 CCAGENT Key，选择主模型、读图、Jev 决策、搜索及语音路由，并查看余额、公开成本和版本。验证和刷新目录不调用收费模型；“测试连接”会发起收费模型请求。CLI 使用 `ccagent account key` 隐藏输入并验证 Key，`ccagent account services` 查看目录，主模型标识为 `ccagent:<路由编号>`。

Key 保存在当前账户的 Windows DPAPI 存储，界面仅显示前缀，不写入模型配置、会话或调用日志。保留个人供应商配置；启用官方辅助服务后，余额、认证或网关失败均不自动切换到个人付费 Key。移除本机 Key 会明确停用官方辅助服务；云端撤销仍在用户中心操作。

`GET /api/account/calls/<Idempotency-Key>` 要求有效登录，返回本账户调用状态、金额、价格快照及结果可用期限；不返回内部 Key、请求哈希或 Blob 标识。Key 撤销后仍可查询本人记录。连接中断时先查原调用；仍在执行或等待核验时不创建另一笔调用，已有可重放结果才按原请求标识取回。

也可使用 `GET /api/account/calls?id=<URL 编码后的 Idempotency-Key>`，仅接受一个 `id` 查询参数，返回和权限与路径接口相同。对恰好为 `.` 或 `..` 的已有合法编号，必须采用查询参数形式，因为 URL 会规范化路径中的点段；可用 `URLSearchParams` 构造参数。以下划线等字符开头的编号也能查询，不需要重新调用供应商。相关兼容与验证记录见 [调用编号恢复](call-recovery-identifiers.md)。

## 管理员备用与用户确认

目录条目的 `limits.fallbackEnabled`、`limits.fallbackRouteId` 描述管理员一级备用策略，`pricing.fingerprint` 为 64 位小写十六进制价格指纹。用户开关默认关闭。Web/桌面显示两路价格后，使用当次 `catalogRevision` 保存明确授权；CLI 使用 `ccagent account fallback --enabled true` 查看价格并确认。目录改变后须重新核对；不自动使用个人供应商 Key。

一次调用先验证两路输入、归属、价格和限制，再冻结两路预算的较大值。只有成功响应被接受前的连接失败或 429/5xx 才在原有整体超时预算内尝试备用；最多一级，不在已开始的流式输出或结果未知时另起一份结果。仅按成功路由的实际用量、汇率及尝试开始时的计价时段结算一次，额外尝试成本和授权上限外差额由平台承担。

`X-CCAGENT-Route-Id`、`X-CCAGENT-Fallback` 表示实际执行路由和是否用了备用；状态查询亦有 `executedRouteId`、`fallbackUsed`，从未派发时执行路由为空。原生日志保留原价格确认，旧调用恢复/重放沿用原标识与快照，不因新设置或调价创建另一笔收费调用。详细规则、检查和发布边界见 [备用路由记录](gateway-fallback.md)。

## 服务接口

| 接口 | 请求与用途 |
| --- | --- |
| `GET /v1/models` | 返回已启用且成本、凭据、协议和汇率配置齐全的服务编号、协议、价格版本、公开来源及限制。 |
| `POST /v1/responses` | 原生 Responses 请求，`model` 填平台路由编号；保留工具调用、推理及流式事件。现有 DeepSeek 主模型使用此接口。 |
| `POST /v1/chat/completions` | 原生 Chat Completions 请求，支持图片、函数工具及流式输出；服务器强制请求最终用量。 |
| `POST /v1/decisions` | `model`、`state`、类型化 `questions`；继续调用 Jev Decisions。不会改写成聊天接口。 |
| `POST /v1/search` | `model`、`query`、`max_results`；Tavily 支持 `search_depth`、`topic`、`time_range`，博查支持 `freshness`。域名过滤使用 `include_domains` / `exclude_domains`。 |
| `POST /v1/voice` | `model`、`text`、可选 `voice`；返回归属本账户的短期 WAV 文件编号，不返回供应商下载地址。 |

聊天和 Responses 必须使用模型目录声明的协议。当前收费网关尚未开放 Anthropic/Gemini 协议；配置不能绕过协议就绪检查。本地个人供应商的既有支持与此开发状态分别验收。

目录另有 `defaults`，以 `chat`、`vision`、`decision`、`search`、`voice` 映射到管理员已保存且当前可用的路由编号，未设置或失效为 `null`。首次验证平台 Key 且未明确提交选择时，客户端可用其初始化角色；已有选择和主动清空的选择不被推荐覆盖，旧目录可以省略该字段。它不自动开启辅助服务、替换个人默认模型或触发收费调用。管理接口、验证与边界见 [平台默认路由记录](gateway-defaults.md)。

Responses 固定为无状态请求：禁止跨调用的 `previous_response_id`、供应商托管会话及后台请求。供应商服务端搜索等额外收费工具尚未定价，不能混入普通 Token 路由；客户端本地工具仍由真实引擎执行权限校验。

## Qwen 输入阶梯与思考模式成本

目录新增 `pricing.definition.tariff.kind=qwen-input-tiers`，包含明确的 `defaultThinking` 和已核定的 `maxThinkingTokens`；三类 `rates` 使用 `tiers`、整数 `upToInputTokens`、`price`，输出档额外含 `thinkingPrice`，不提供误导性的首档固定 `price`。边界对三项一致，按实际输入总量（含缓存）选择整次请求的一档。客户端须保留并展示完整结构，不能将其简化成旧固定价格。

该策略派发前固定 `enable_thinking` 布尔值；未指定时使用已确认的默认模式。思考预算另计供应商最大思考长度，实际结算使用可核实完整输出。`priceTier` 在调用用量或管理员检测结果中记录实际输入总数、所选档位上限与模式。配置、默认模式或思考上限改变会进入新价格指纹；相关行为、测试边界和供应商待确认项见 [Qwen 阶梯计费记录](qwen-tiered-pricing.md)。

## 大文件与结果

直接 JSON 请求上限为 3 MiB。较大请求先使用 `POST /api/files` 申请 `purpose=request` 的私有上传，再按返回的 PUT URL 和完整 `headers` 上传；其中 `x-content-type` 是 Blob 对象类型验证所必需的请求头。上传授权 2 分钟有效，文件默认保留 15 分钟。

上传后调用 `POST /api/files/<id>` 完成大小与类型核对。网关接受 `{ "request_file_id": "<本账户的请求文件 UUID>" }` 读取完整 JSON。不能在同一封装中再附带覆盖字段。

原生客户端对超过 3 MiB、最多 32 MiB 的完整 JSON 自动使用此流程。上传仅接受官方签名 API 地址及匹配当前用户的对象路径，不携带账户 Cookie 或平台 Key，不跟随跳转；读取时校验实际解码字节数，不将 CDN 的传输长度误当成原文件大小。请求文件在结果读完后申请删除，异常残留依照短期有效与清理策略处理。

图片也可先上传为 `purpose=image`，在正常图片输入位置填写 `ccagent-file:<图片 UUID>`。服务器校验文件归属、用途、状态和期限后才读取和冻结额度。其他账户的编号返回 404。

语音响应的 `audio.file_id` 通过 `GET /api/files/<id>` 鉴权下载。删除使用 `DELETE /api/files/<id>`。底层存储为私有 Blob，匿名不能读取；过期文件拒绝访问，并由维护任务实际删除。

## 冻结、结算与异常

调用先原子校验账户、Key 和余额，再冻结授权预算；纯文本依据有余量的字节上界与输出限制计算预算，图片等输入按路由上下文上限保守授权。预算不是实际账单。

每次调用记录成本版本、公开来源、币种、汇率、1.3 倍率及价格时间。最终按供应商可核实用量结算并释放剩余额度。供应商异常超出授权预算的部分由平台承担，不临时加扣用户余额；相关差额写入调用记录。

内部重试仅对最终成功响应向用户结算一次，额外尝试由平台承担。流式连接取消后，服务器会在原超时范围内继续读取最终统计；已有可核实用量时按统计结算，无法核实时转为待核验。24 小时后仍无法核实的冻结由维护任务释放，不估算 Token 扣款。

`X-CCAGENT-Call-Id` 返回数据库调用编号。典型状态包括 401 未登录、403 Key/权限无效、402 余额或额度不足、409 幂等冲突/处理中、410 结果过期、502 上游未完成。发生网络错误后应先查询调用状态，不自动更换幂等键重复发起。

服务目录停止提供某个路由后，“刷新服务目录”会清除对应选择，保留其他有效选择。原默认官方主模型失效时，客户端保留不可用提示，要求用户重新选择，不自动代用个人付费模型。供应商账单与资金结果始终以云端账本为准；数据库或连接超时不会视为已成功结算。

## 后台管理员连接检测

管理员使用当前应用会话及 `routes.write` 权限访问 `GET /api/admin/routes/test?routeId=<编号>`，免费读取已保存配置的固定测试说明、成本估算和确认指纹；检测允许暂停路由，但仍检查主机、凭据、价格及汇率。`POST` 仅接受 `routeId`、UUID `testId`、`confirmationFingerprint` 和 `confirmPlatformCost=true`，并校验准确来源；不需要个人消费 Key。配置或价格改变后的旧确认返回 409，未确认费用或额外字段返回 400。

新检测返回 202，通过 Next.js `after()` 执行单次、有界的真实供应商请求，最长 30 秒，不重试或使用备用；平台承担成本，用户扣费固定为零。`GET` 同一路径并附带 `testId` 查询原结果，完成后的相同请求返回 200 重放，不再联系供应商。结果含编号、状态、时段/价格/汇率快照、可核实用量、公开成本、耗时及安全 HTTP 状态，不含供应商原文或密钥。未知结果明确标记，历史开始/结果各追加一条不可变审计。

本节描述后台运营检测；应用设置中的模型测试继续遵循所选服务的计费规则。完整协议、验证和发布边界见 [后台连接检测记录](gateway-connection-tests.md)。

## 定时维护

`cloud/vercel.json` 配置每分钟调用 `/api/system/maintenance`，处理过期调用、私有文件清理和七支付订单补偿。该接口使用独立 `CRON_SECRET`，个人 Key 和应用会话不能替代系统身份。接口实现支持重复执行；资金操作按数据库唯一引用防止重复结算。退款未知结果不进入自动重发流程。

该定时配置在部署并配置密钥后才会实际运行。目前源码和数据库隔离检查已通过，尚未认定线上定时任务已启用。
